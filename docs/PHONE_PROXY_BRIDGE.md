# 📱 جسر الهاتف — عنوان Binance الشخصي الخاص بك (v5.33)

> **الفكرة**: بدلاً من أن يخرج البوت إلى Binance من عنوان IP مشترك مع مئات
> خدمات Render المجانية (مصدر حلقات الحظر 418 المتكررة)، نمرر حركة Binance
> عبر **هاتفك الشخصي** — فترى Binance عنوانك الشخصي (واي فاي منزلك أو بيانات
> جوالك) الذي لا يشاركه معك إلا عدد ضئيل من الناس.

---

## لماذا هذا الحل هيكلي؟

| | Render (IP مشترك) | جسر الهاتف (IP شخصي) |
|---|---|---|
| من يشاركك العنوان؟ | مئات الخدمات المجانية (بينها بوتات ومحاولات كثيرة تضرب Binance) | أفراد منزلك فقط (واي فاي) أو مستخدمو خلية البرج (بيانات الجوال، وتُبدَّل تلقائياً) |
| مصدر الحظر 418 | جيرانك يكسبون البان وأنت ترثه | عملياً معدوم |
| التكلفة | $0 (مع توقفات متكررة) | $0 (بضاعات كهرباء زهيدة) |
| ماذا لو انطفأ الهاتف؟ | — | البوت **لا يموت**: يتراجع تلقائياً للمسار المباشر (v5.33) ويعود لهاتفك فور عودته |

**كمية البيانات عبر الهاتف ضئيلة جداً**: بعد v5.31 صار كل تتبع الأسعار
والشموع عبر WebSocket مباشرة من Render (لا يمر بالهاتف). الهاتف يحمل فقط
نداءات REST النادرة (تهيئة أولية، إعادة ملء فجوات، المسبار) — بضعة
ميغابايت في اليوم كحد أقصى.

## كيف يعمل تقنياً؟ (3 قطع)

```
[ Binance API ]
       ↑ (يظهر له عنوانك الشخصي)
[ هاتفك ]  ← تطبيق Tailscale فقط، وضع "Exit Node"
       ↑ (نفق مشفر داخل شبكة Tailscale)
[ Render ] tailscaled (وضع userspace) + البوت
       ↑
BINANCE_PROXY_URL=socks5h://127.0.0.1:1055
```

1. **الهاتف**: يصبح "Exit Node" في شبكة Tailscale الخاصة بك — أي أن أي جهاز
   في الشبكة يختار الهاتف كبوابة خروج للإنترنت.
2. **Render**: يشغّل `tailscaled` بوضع userspace (لا يحتاج صلاحيات TUN) +
   يختار هاتفك كـ exit-node، ويكشف SOCKS محلي على `127.0.0.1:1055`.
3. **البوت**: `BINANCE_PROXY_URL=socks5h://127.0.0.1:1055` يوجّه كل REST
   عبر هذا المسار (v5.30 أصلها موجود، وv5.33 أضاف الصحة والتراجع التلقائي).

> **لماذا Tailscale؟** هاتفك خلف NAT (لا يمكن لـ Render الاتصال به مباشرة).
> Tailscale يحل هذا بنفق معكوس مجاني، بعنوان ثابت `100.x.y.z` لا يتغير
> أبداً، وبلا بطاقة، وحتى لو منع الاتصال المباشر (P2P) يمر عبر مرحّلاتهم
> تلقائياً.

## خطوات التفعيل (10 دقائق)

### الخطوة 1 — الهاتف: Tailscale

1. ثبّت **Tailscale** من متجر التطبيقات (مجاني، بلا بطاقة).
2. سجّل دخولاً (Google/GitHub/Apple — ستنشأ شبكة خاصة تلقائياً).
3. من قائمة التطبيق: فعّل **"Exit node"** (Use this device as an exit node).
4. **مهم**: اعفُ التطبيق من تحسين البطارية:
   إعدادات أندرويد → التطبيقات → Tailscale → البطارية → **غير مقيّد**.
   (وإلا قد يوقف أندرويد النفق عند النوم).
5. دوّن اسم جهازك وعنوانه داخل الشبكة (يظهر في التطبيق، مثل `100.101.102.103`).

### الخطوة 2 — موافقة على Exit Node (مرة واحدة)

1. افتح <https://login.tailscale.com/admin/machines> من أي متصفح.
2. بجانب الهاتف: ⋯ → **Edit route settings** → فعّل **"Use as exit node"** → Save.

### الخطوة 3 — مفتاح المصادقة

1. <https://login.tailscale.com/admin/settings/keys> → **Generate auth key**.
2. النوع: **Reusable**، الصلاحية: 90 يوماً (جدّدها عند الانتهاء).
3. انسخ المفتاح (يبدأ بـ `tskey-auth-...`).

### الخطوة 4 — Render: ثلاثة متغيرات

في لوحة Render → Environment، أضف:

| المتغير | القيمة |
|---|---|
| `BINANCE_PROXY_URL` | `socks5h://127.0.0.1:1055` |
| `TS_AUTHKEY` | `tskey-auth-...` (المفتاح من الخطوة 3) |
| `TS_EXIT_NODE` | عنوان الهاتف `100.x.y.z` (أو اسمه) |

ثم **Manual Deploy** (أو ادفع أي تحديث — autoDeploy يلتقطها).

### الخطوة 5 — التحقق

افتح `/api/health` وابحث عن القسم الجديد:

```json
"binance_proxy": {
  "configured": true,
  "scheme": "socks5h",
  "healthy": true,
  "using": "proxy",          ← المسار يعمل عبر هاتفك
  "retry_in_s": 0,
  "last_fail_reason": null
}
```

كما سيظهر جهاز `crypto-bot-render` متصلاً في لوحة Tailscale الإدارية.

## ماذا يحدث حين ينام الهاتف أو يخرج من التغطية؟

هذا بالضبط ما بناه v5.33 (مسار مُدار بصحة + تراجع):

```
الهاتف متاح     →  كل REST عبر هاتفك            (using: "proxy")
الهاتف ينام     →  فشل اتصال واحد فقط يكفي:
                   تراجع فوري للمسار المباشر    (using: "direct-fallback")
                   لمدة BINANCE_PROXY_RETRY_S (300ث افتراضياً)
الهاتف عاد      →  مسبار وزن-صفر /ping عبر الهاتف
                   → عودة تلقائية للمسار        (using: "proxy")
```

**قاعدة ذهبية مضمّنة في الكود**: استجابات الحظر (418/429) **ليست** فشلاً
شبكياً ولا تقلب المسار أبداً — إذا حُظر عنوان هاتفك يبقى الحظر عليه ولا
ننقل المشكلة إلى عنوان Render. الأخطاء الشبكية فقط (هاتف غير reachable)
هي ما يفعّل التراجع.

سلوك المراقبة أثناء التراجع:
- مسبار واحد فقط كل نافذة (لا stampede على هاتف ميت — القفل يمنع التزامن).
- مسبار ما بعد الحظر (`_send_probe`) يتحقق من **المسار النشط حالياً**،
  لا مسار ثابت.
- سجل البوت يوضح كل انتقال:
  `proxy route UNREACHABLE - falling back to DIRECT egress for 300s`
  ثم `proxy route RESTORED - egress back via the phone bridge`.

## أسئلة شائعة

**هل بيانات الجوال ستُستهلك كثيراً؟** لا — ميغابايتات قليلة يومياً (REST
فقط). الشموع والأسعار اللحظية كلها عبر WebSocket مباشرة من Render.

**على WiFi أم بيانات؟** كلاهما يعمل. WiFi أفضل (هاتف على الشاحن في البيت =
توفر ~24/7). بيانات الجوال تعمل أيضاً وتمنحك ميزة إضافية: عنوانك يتغير
دورياً — إذا حُظر نظرياً يكفي وضع الطيران وإيقافه لعنوان جديد نظيف.

**هل Tailscale يرى حركاتي؟** النفق مشفر طرف-لطرف بين أجهزتك؛ Tailscale
(مرحّلات DERP عند الحاجة) يرى بيانات مشفرة فقط. حركة Binance TLS أصلاً
فوق البروكسي.

**أريد إلغاء الجسر مؤقتاً؟** امسح `BINANCE_PROXY_URL` من Render وأعد النشر —
أو فقط أطفئ Exit node من الهاتف: البوت يتراجع للمسار المباشر تلقائياً
ويواصل العمل (راقب `using` في health).

**هل هذا يعالج وضع التداول الحي (live orders) من أمريكا؟** لا — أوامر
الإيثار الموقّعة تذهب إلى `api.binance.com` الذي يُحظر جغرافياً من الولايات
المتحدة. هذا الجسر يعالج الحظر بسبب الوزن (418/429) وليس الحظر الجغرافي.
للترقية الجغرافية لاحقاً: نفس آلية `BINANCE_PROXY_URL` مع بروكسي خارج
أمريكا.
